IoT / ENGINEERING NOTE

가상 게이트웨이로
TCP 수집 서버 검증하기

기존 EC2와 DB에서 500대 목표를 감당하는지 확인하고, 부하를 늘렸을 때 드러나는 한계를 조사했습니다.

목표와 수집 구조

냉매와 콜드체인은 조회 요구가 달라도 TCP로 센서 데이터를 수집하는 구조는 같았습니다.
공통 TCP 수집과 device-core의 장비 모델 / 설정을 재사용하고, 조회와 알림은 서비스별로 확장할 수 있도록 경계를 잡았습니다.

TCP 수신완전한 프레임까지 버퍼링 후 파싱
→
저장과 응답Outbox 기록 / 커밋 후 ACK
→
이벤트 전달별도 작업의 HTTP 전송과 실패 재시도

부분 송신과 송신 순서를 처리하기 위해 큐를 두고 Selector 스레드가 실제 송신을 담당했습니다.
TCP 입출력과 데이터 처리 작업을 분리한 뒤 배포된 EC2에서 DB 저장과 ACK까지 시험했습니다.

시험 환경과 방법

500대는 1차 양산 검토 규모였습니다.
기존 EC2와 DB로 목표를 감당하는지 확인하고, 성장 가능성을 고려해 1,000대까지 시험했습니다.
PoC와 DB 인스턴스를 공유하되 시험 스키마를 분리했습니다.

시험 결과

동시 접속 시험확인 결과판단
500대 × 5회2,500건 모두 10초 이내 ACK시험 환경에서 목표 규모 확인
1,000대 첫 회차연결 성립, 114건은 10초 내 ACK 미수신커넥션 대기 / 쿼리 / 커밋 지연의 영향으로 판단

부하 증가에 따른 병목 확인

로컬에서는 풀 크기를 50으로 늘려 응답이 빨라지는 것을 확인했습니다.
공유 DB 자원을 사용하고 500대 목표를 충족했으므로 배포 환경의 풀 조정은 보류했습니다.

시나리오와 지표는 직접 설계하고, 생성형 AI를 활용해 Node.js 가상 게이트웨이 시험 화면을 구현했습니다.
회차별 결과를 시각화하고 JSON으로 남겼습니다.
