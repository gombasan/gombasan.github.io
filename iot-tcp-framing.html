IoT / ENGINEERING NOTE

TCP 바이트 스트림에서
장비 메시지 복원하기

실제 장비 연동 중 메시지가 나뉘어 들어오면 파싱이 실패했습니다. 수신 바이트를 연결별로 누적하고, 일부만 전송된 응답은 다음 쓰기에서 이어 보내도록 개선했습니다.

문제 확인과 원인 분석

TCP는 바이트 스트림이라 애플리케이션 메시지의 경계를 보존하지 않습니다. 장비가 보낸 메시지 한 건이 여러 번의 read()에 나뉘거나, 메시지 여러 건이 한 번에 읽힐 수 있습니다. 읽은 데이터를 바로 메시지 한 건으로 해석하면 미완성 프레임을 파싱하게 됩니다.

비차단 소켓의 write()도 버퍼 전체를 한 번에 받아들이지 않을 수 있습니다. 남은 바이트를 보관하지 않으면 응답 일부가 전송되지 않은 채 남습니다.

개선

수신 버퍼에서 완성된 프레임만 처리

연결별 버퍼에 읽은 바이트를 누적하고, 완성된 프레임만 분리해 파싱했습니다. 한 번의 읽기로 여러 프레임이 들어오면 순서대로 처리하고, 끝에 남은 미완성 프레임은 다음 읽기까지 보존했습니다.

분할 수신 테스트 코드 보기

첫 16바이트만 들어왔을 때 디코더가 결과를 반환하지 않고, 버퍼의 읽기 위치도 그대로인지 확인합니다. 이후 compact()로 남은 데이터를 보존하고 나머지 바이트를 붙인 뒤, 원래 메시지가 복원되는지 검증합니다.

Java
@Test
void waitsUntilTheEncryptedFrameIsComplete() {
    byte[] encryptedPacket = encode(plainPacket);
    ByteBuffer inbound = ByteBuffer.allocate(128);

    inbound.put(encryptedPacket, 0, 16);
    inbound.flip();

    assertThat(codec.decodeInbound(inbound)).isEmpty();
    assertThat(inbound.position()).isZero();

    inbound.compact();
    inbound.put(encryptedPacket, 16, encryptedPacket.length - 16);
    inbound.flip();

    assertThat(codec.decodeInbound(inbound).orElseThrow().plainPacket())
        .containsExactly(plainPacket);
    assertThat(inbound.hasRemaining()).isFalse();
}

송신 큐에서 남은 응답 이어 보내기

Selector 스레드에서 연결별 송신 큐를 관리했습니다. 쓰기 후 바이트가 남아 있으면 같은 ByteBuffer를 큐에 유지하고, 소켓이 다시 쓰기 가능한 시점에 남은 위치부터 전송했습니다. 앞 응답을 모두 보낸 뒤 다음 응답을 처리해 송신 순서를 유지했습니다.

부분 송신 처리 코드 보기

write()는 전송한 만큼 버퍼의 위치를 이동시킵니다. hasRemaining()이 참이면 큐의 현재 버퍼를 유지한 채 반환합니다. 버퍼가 비워진 뒤에만 completeCurrentWrite()를 호출해 다음 응답으로 넘어갑니다.

Java
while (context.hasPendingWrites()) {
    ByteBuffer buffer = context.currentWriteBuffer();
    int bytesWritten = client.write(buffer);
    if (bytesWritten > 0) {
        context.onBytesWritten();
    }

    if (buffer.hasRemaining()) {
        return;
    }

    context.completeCurrentWrite();
}

key.interestOps(key.interestOps() & ~SelectionKey.OP_WRITE);

재검증

  • 미완성 프레임은 대기하고, 후속 데이터가 도착하면 완성된 메시지로 처리하는지 테스트했습니다.
  • 연속해서 들어온 여러 프레임을 순서대로 분리하는지 확인했습니다.
  • 부분 송신 후 남은 바이트부터 이어 보내고, 다음 응답이 앞서 전송되지 않는지 검증했습니다.
